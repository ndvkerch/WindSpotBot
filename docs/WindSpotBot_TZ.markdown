Техническое задание: WindSpotBot
1. Общее описание
Название: WindSpotBotЦель: Telegram-бот для кайтсерферов с функциями чек-ина, планирования, просмотра спотов, прогноза погоды, уведомлений, чатов с хэштегами, оценки спотов и админ-статистики. Подготовка к будущему веб-приложению.Платформа: Telegram, библиотека aiogram 3.x.Язык: Python 3.10+.Целевая аудитория: Кайтсерферы, администраторы спотов.Сообщество: @WindSpotRU для обсуждений и новостей.Особенности:  

Морской, кайтерский, сёрфовый тон с юмором («лови ветер», «йо, бро»).  
Тематические эмодзи: 🤙, 💨, 🏄‍♂️, 🌊, 🪁, ☀️.  
Изолированные сервисы и репозитории для масштабируемости.  
Конфигурация через .env с валидацией pydantic.  
Тестирование (покрытие >80%) и документация.

2. Функциональные требования
2.1. Основные команды и сценарии

Команда /start:

Регистрирует пользователя (ID, имя, username, часовой пояс по геолокации).  
Показывает приветствие:  🤙 Йо, {name}! Добро пожаловать на борт WindSpotBot! 🏄‍♂️
Лови ветер, находи споты и тусуйся с кайтерами! 💨
💬 Заходи в @WindSpotRU, там волна новостей и движухи!


Динамическое меню (например, «Покинуть спот» для чек-ина типа 1).  
Логирование: INFO: Пользователь user_id=123 вызвал /start.


Чек-ин:

Тип 1 («На месте», ✅):  
Реализовано: выбор спота, длительности (1-6 часов), автодеактивация по истечении времени.  
Ограничение: один активный чек-ин (типы 1 или 2).  
Использует кэшированную геолокацию (TTL=1 час).  
Показывает ближайшие споты (NEARBY_SPOTS_LIMIT).  
Сообщения в кайтерском стиле с эмодзи:  ✅ Йо, ты на Спот 1! Лови вайб! 🏄‍♂️
Сколько тусить будешь?
[1 час] [2 часа] [3 часа] [4 часа] [5 часов] [6 часов]




Тип 2 («Прибуду», ⏳): Время до прибытия 1-3 часа, автодеактивация/удаление (не реализовано).  
Тип 3 («Планирование», 📅): Дата (до 7 дней), время, спот (не реализовано).  
Уведомляет админов и пользователей в теме спота через NotificationService.


Планирование посещений:

Чек-ин типа 3 (не реализовано).  
Данные: спот, дата, время.  
Отображается на страничке спота (N записей, PLANNED_VISITS_LIMIT):  📅 Планы на волну:
1. 20.04.2025 14:00, <a href="tg://user?id=123">@ivan123</a>
2. 21.04.2025 10:00, <a href="tg://user?id=456">@anna</a>




Кто на спотах:

Список активных спотов (N, в .env) с погодой и пользователями (без кэша):  💨 Ветер гонит волну! Проверяй, кто тусит:
🏄‍♂️ Спот 1 (1.2 км)
💨 Ветер: 5 м/с (порывы 7 м/с), СЗ
👥 На месте: @ivan123 (ещё 2 часа)
⏳ Прибудут: @anna (через час)
📅 Планы: @petr (20.04.2025, 14:00)




Сообщения/чаты спотов:

Реализовано: чаты спотов как отдельные темы в групповом чате @WindSpotRU.  
Управление через TopicService.  
Фильтрация сообщений по хэштегам (например, #Спот1).  
Команда /filter #Спот1 для просмотра сообщений по хэштегу.  
Уведомления о чек-инах отправляются в темы спотов:  🪁 @ivan123 зачекинился на #Спот1: Ветер огонь! 🤙




Страничка спота:

Данные: название, геолокация, описание, погода, рейтинг, статистика, планы.  
Кнопки: чек-ин, планирование, чат, избранное, оценка.  
Пример:  🏄‍♂️ **Спот 1**
📍 1.2 км от тебя
💨 Ветер: 5 м/с (порывы 7 м/с), СЗ
🌊 Вода: 18°C
⭐ Рейтинг: 4.5 (10 оценок)
👥 На месте: @ivan123
[Чек-ин] [Планировать] [Чат] [⭐ Оценить]




Оценка спотов:

Оценка (1-5) через страничку спота.  
Уведомление после завершения чек-ина типа 1 (кнопка «Покинуть» или автодеактивация), задержка 5 минут:  🪁 Как тебе Спот 1? Дай вайб от 1 до 5! 🤙
[Оценить Спот 1]


Одна оценка на пользователя, с возможностью изменения.


Команда /help:

Описание функций с морским тоном:  ❓ **Лови волну помощи, бро!**
📍 /start — врывайся в движ!
✅ Отметиться — лови спот!
🔍 Кто на спотах — чекни тусу
💨 /weather — ветер в паруса
💬 Обсуждай вайб в @WindSpotRU! 🤙




Админ-функции:

/admin_notifications: управление уведомлениями.  
/broadcast: рассылка.  
/stats (низкий приоритет): пользователи, споты, чек-ины, топ-5 спотов (кэш, TTL=10 минут).



2.2. Уведомления

Персонализированные, с морским тоном:  🔔 Йо, {name}! На Спот 1 новый чек-ин от @anna! Лови волну? 🤙


Отправка в темы спотов через NotificationService.

2.3. Планировщик задач

SchedulerService для:  
Проверки чек-инов (CHECKIN_CHECK_INTERVAL_MINUTES).  
Обновления погоды (WEATHER_CHECK_INTERVAL_MINUTES).


Реализация через APScheduler.

2.4. База данных

Тип: SQLite (data/database.db), миграции через alembic.  
Таблицы:  
users: ID, имя, username, часовой пояс.  
spots: ID, название, координаты, описание.  
checkins: ID, user_id, spot_id, тип, время, статус.  
spot_ratings: user_id, spot_id, оценка.



3. UX/UI
3.1. Принципы

Тон: Морской, кайтерский, сёрфовый, с юмором («лови ветер», «йо, бро»).  
Эмодзи: 🤙, 💨, 🏄‍♂️, 🌊, 🪁, ☀️.  
Клавиатуры: Inline (до 3 кнопок в ряду), Reply (геолокация, текст).  
Ошибки:  🌊 Упс, волна унесла твою геолокацию! 😎 Отправь ещё раз, бро!

4. Архитектура

Сервисы: GeoService, SpotService, CheckinService, TopicService, NotificationService.  
Репозитории: UserRepository, SpotRepository, CheckinRepository.  
Кэширование: Геолокация (TTL=1 час).  
Логирование: Через logging.config.  
Тестирование: pytest, покрытие >80%.

5. Приоритеты

Высокий: Чек-ины типа 1, чаты спотов, уведомления, страничка спота.  
Средний: Чек-ины типов 2 и 3, планирование, оценка спотов.  
Низкий: /stats, геймификация.
